# 污水处理厂工艺管控平台

面向污水处理厂进出水监测、工艺单元、加药曝气、污泥处置与达标排放的一体化工艺管控后台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 本地开发自检

构建后、或改完达标审核相关代码后，跑一条命令把后端真实起起来，自检三段流程与边界场景：

```bash
make check            # 前端类型检查+构建，再起后端自检
# 或只跑后端：
cd backend && python3 devcheck.py
# 已手动起好服务时，可对现成进程自检：
python3 backend/devcheck.py --url http://127.0.0.1:8000
```

自检覆盖：列表/详情/导出一致、空数据空页、`待审核→审核中→已通过/需整改`、
超标时禁止确认通过、重复下发拦截、登记校验（缺字段、非负整数、重复审核编号），
退出码非 0 即有失败项。

## 达标审核状态机

状态机只有一份实现：`backend/app/statemachine.py` + `services/audit.py` 中的
`STATE_MACHINE`。前端不再硬编码动作/状态，统一读 `GET /api/audit/meta`，
列表和详情的每条记录都会带当前 `可执行动作`，因此同一审核编号两边判断永远一致，
不会再出现「点不动」的动作。

流转口径：

| 当前状态 | 可执行动作 | 说明 |
| --- | --- | --- |
| 待审核 | 开始审核 | 不能直接通过或下发整改 |
| 审核中 | 确认通过 / 下发整改 | 超标次数大于 0 时「确认通过」被守卫拦下，须先下发整改 |
| 已通过 | （无） | 终态，重复操作会提示无需重复操作 |
| 需整改 | （无） | 终态；重复下发整改会被拦下并说明，新问题走新一轮登记 |

补充口径：

- 空数据：筛选无结果返回空页（`items: []`、`total: 0`），导出同理，不当作错误。
- 超标次数：非负整数，空值按 0 处理；负数或文本会被拦下并说明。下发整改时整改项数按超标次数落值。
- 重复下发：需整改为终态，再次下发返回可读提示，不产生重复整改单。
- 列表与详情共用同一序列化，字段、审核状态、可执行动作完全一致。
- 既有审核记录（AUDI-0001～0003）的编号与状态保持不变；另补了一条「需整改」示例 AUDI-0004。


## 业务模块

| 模块 | 目录 | 业务对象 | 主要字段 |
| --- | --- | --- | --- |
| 厂区单元 | `plant` | 工艺单元 | 单元编码、单元名称、处理工艺 |

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断；状态/动作的判定统一走
  `app/statemachine.py`，前端通过模块的 `/meta` 接口读取，不在两边各写一份。
